# 2026-10-18 听写润色提示词改版（D-038）

## 范围

GAP-023。改写听写润色提示词，建一个原创的评测集。

刻意没做：
- “AI 对话”应用类别
- 关闭推理模型的思考（各服务商参数不同）
- 风格学习：与 D-012“读到的文字不保存”冲突，需要新决策
- 光标上下文（B-002）

## 改动

- `src/main/polish.ts` 的 `buildPolishPrompt`：
  - 固定部分（规则 + 9 个原创示例）在前，“本次整理”（场景、指定输出语言、词表）在后，场景、词表变化时 system 的开头不变。
  - 新规则：
    - 说明原文来自语音识别：标点可以重新断句，能确定的同音错字直接改正。
    - 数字用阿拉伯数字（成语、约数除外）。
    - 中英文之间加空格，中文用全角标点。
    - 口述“换行”执行为换行。
    - 不做简繁转换。
  - 原“不增删信息”与删填充词、改口规则矛盾，改为“不添加原文没有的信息，不改变原意和语气”。
  - 代码场景去掉“行文简短”（可能让模型删掉细节）。
- `test/fixtures/polish-eval.json`：37 条原创用例，每条带人工写的理想输出和检查条件。
- `scripts/polish-eval.ts`：用环境变量里的 LLM 依次跑新、旧两版提示词，报告通过数、分组通过数和耗时中位数，`--out` 输出全部结果。

## 验证

- `npm run test`：通过 99、失败 0、跳过 17（新增 4 条润色测试，包括理想输出都能通过检查、评测输入不与示例重复）。
- `npm run typecheck`、`npm run build`：通过。
- 评测脚本用本机假 LLM 服务（原样回显）跑通。没有用真实模型跑：需要真实 Key（人工门禁）。

## 遗留

- 用真实模型跑 `scripts/polish-eval.ts` 对比新旧通过数和耗时；PIPE-016 真机验证。
- 提示词变长（约 1.1k 字），不支持前缀缓存的服务首字延迟可能略增，以评测耗时为准。
