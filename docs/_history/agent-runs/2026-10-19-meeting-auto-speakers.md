# 2026-10-19 参会人数恢复“自动”、改进区分说话人与声纹认人（D-042）

## 范围

GAP-025。用户要求“参会人数还是把自动加上，并且优化声纹识别策略”。用户确认默认自动；遇到的问题：说得少的人被并掉、同一个人被拆成两个、保存的声纹认不出或认错。

刻意没做：
- 只说一两句的人仍然不单算一个人：自动人数在这里本身判不准，用户可以改成具体人数。
- 长会议里同一人的杂音小组偶尔多分出一个人（用户 7 路会议里有 2 路）。再收紧就会漏掉说得少的真人。
- 每 20 秒整体归类的耗时没有优化：2454 句时自动约 1.3 秒，已知人数约 0.7 秒，都是两两相似度的 O(n²)。

## 改动

- `cluster.ts` 的 `regroup`：
  - 平均链接切成细分组（0.45），至少 3 句的组和有约束标签的组作为候选，同一标签的组先并成一组。
  - 反复合并“分不开”的两组：组间平均相似度 + 0.15 / √n ≥ 0.8 × 较散一组的组内相似度。
  - 已知人数时合并到 k 组；`AUTO_SPEAKERS`（0）时合并到两两分得开，最多 10 人。
  - 自动人数在每句重新归属后复检（`weakestPair`）：不到 3 句的组、句数不到这一路 5% 且与大组相似度高于大组组内 0.55 倍的小组并掉。
- `printScore` 改为两边各减去 `SPEAKER_BACKGROUND`（`background.ts`：AliMeeting 12 人、AISHELL-1 14 人，每人平均后两数据集等权）后的余弦。`PRINT_MATCH` 0.6，`PRINT_MIN_SEGMENTS` 3。
- `meeting/index.ts`：
  - 人数 0 为自动；在线归类最多比上次整体归类多 1 人（`autoCap`）。
  - 声纹自动认出的名字（新列 `meeting_speakers.auto_named`）不作为归类约束，每次整体归类后复核，低于 `PRINT_KEEP` 0.5 撤掉。
  - 自动人数时，没名字又最像本路已认出某人的组并给他。
  - 自动认出的人只在整场仍 ≥ 0.6 时更新声纹；用户改名时清除 `auto_named`。
- 设置默认 `meetingSpeakers` / `meetingRemoteSpeakers` 为 0。主窗口的开会卡片和说话人栏增加「自动」，自动时说话人栏显示「自动（N 人）」。
- `scripts/speaker-eval.ts`：用公开数据的逐句声纹评测自动人数、已知人数与声纹认人。

## 验证

- 离线评测：AliMeeting 3 场 × 4 人的逐句声纹（2454 句）、AISHELL-1 14 人（795 句），加上用户本机 7 路会议的逐句声纹（只导出声纹与说话人编号，没读文字，用完已删），共 283 个场景。自动人数判对的场景：

  | 方法 | 判对 |
  | --- | --- |
  | 新方法 | 221 |
  | 旧自动（D-020） | 150 |
  | 只用合并、不复检小组 | 227（正常会议多分出人） |
  | NME-SC 谱聚类 | 197 |

  新方法分类明细见 D-042。`node scripts/speaker-eval.ts`（不含用户会议，264 个场景）：判对 205 个；声纹同场 3 句一组漏认 0.4%、别人过线 0.2%。
- 会中模拟（按时间逐句在线归类，每 10 句整体归类一次）：76 场里最终人数判对 72 场，平均每场人数变化 0.9 次。
- 打包版隔离实例（`/tmp/mt smoke/ud`，用户数据库的副本）：
  - 新列迁移正常。新用户默认显示「现场人数：自动」「线上人数：自动」。
  - 4 场会议改为自动后，已命名的人与人数不变。
  - 清空名字模拟“新会议 + 已有声纹”：8 个人全部认对（含此前没认出的 1 场），没有认错；2 路各多出一个 10～15 句的小组。
  - 发现并修复一个问题：同一个命名过的人的句子落在几个细分组时，被拆成几个只有 1 句的新说话人。已补测试。
  - 测试实例开着时监听了 Fn 约 10 分钟：用相对路径启动，`pkill` 没匹配上。
- `npm run typecheck`、`npm run test`（通过 136、失败 0）、`npm run build`、`npm run docs:check` 通过；`npm run dist` 成功。
