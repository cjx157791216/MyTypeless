# 2026-10-21 线下三人会议识别差：会中起名锁死说话人、切点切在字中间

## 范围

GAP-026（D-042 范围内的修复）。用户反馈：今天两场线下会议（3 人、小会议室、一张桌子）识别准确率很低。临时录音整理后已删除，只能用数据库里的逐句声纹和转写文字分析。

刻意没做：
- 用 LLM 校对转写文字（同音错字“两平→两瓶”等）：改变用户看到的转写，需要负责人决定。
- FireRedASR2 在不到约 10ms 的音频上会让 `mt-diarize` 进程崩溃：会议段至少 1 秒、实际碰不到，没改。

## 发现

- 27 分钟那场选了 3 人，结果是设计师 221 句、胡 111 句、第三人（没名字）只有 4 句；用 10-18 会议里成、胡的逐句声纹作参照，约 37 句更像成，其中 35 句被归在“设计师”下。
- 原因：`applyRegroup` 把用户起过名的人的所有句子当作约束（不挪动）。会中给设计师起名时组里已混进成的话；达到人数后新句子只归入最像的人，下一次整体归类又被锁住，越积越多。按时间逐句模拟（在线归类 + 每 20 秒整体归类）：不起名时成被分出 28 句；第 1、3、10 分钟起名后成的 36 句全部并进设计师、胡被拆成两组。5 分钟那场第 1 分钟起名时三个人被并成一组。
- 32%（108/336）的段是句内按窗口切开的；窗口每 0.5 秒一个，切点常在字中间（“一进‖门”）。

## 改动

- `cluster.ts`：`regroup` 先用软约束（命名过的人只认领自己句子最多的组，组里别人的句子照常挪走），有命名过的人认领不到组时退回原来的硬约束；手动改归属的句子仍不动。
- `segmenter.ts`：`snapCuts` 把句内切点挪到 ±0.25 秒内最安静的 10ms 处；`index.ts` 的按窗口切开后使用。
- 模块说明补充两条不变量；验收 MEET-031。

## 验证

- 用户会议声纹回放：按 3 人重新区分并保留“设计师”的名字，结果设计师 193 / 胡 113 / 成 30 句，成的组按声纹认人得分 0.64（门槛 0.6）自动标出；任意时刻起名，模拟结果都与不起名相同。
- 合成接话（系统 Tingting / Meijia 朗读的 12 对句子首尾相接，切点偏离换人处 ±50～250ms，本机 FireRedASR2 int8 识别）：两人间停顿 60ms 时错字率 原切点约 1.9% → 挪到安静处约 0.7%（整句不切约 0.8%）；完全不停顿时 1.9% → 1.9%。
- `npm run typecheck`、`npm run test`（通过 143、失败 0；新测试在旧代码上失败）、`npm run build`、`npm run docs:check` 通过。
