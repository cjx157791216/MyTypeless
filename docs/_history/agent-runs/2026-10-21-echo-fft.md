# 2026-10-21 回声去除的 FFT 提速

## 现象

Windows 低压 4 核笔记本上开“现场 + 线上”的会议，主进程周期性卡顿。给运行中的主进程采 90 秒 CPU 剖析：最长的 5 段连续忙碌（0.3～0.5 秒）都在 `echoFree → removeEcho → features → fft`，每句话都要做一次；当时机器另有程序占用较多 CPU，卡顿被放大。

## 原因

`echo.ts` 的 `fft` 在每个蝶形运算里重新计算 `Math.cos` / `Math.sin`，交换元素用解构（每次分配数组）。NFFT 固定 512，每帧一次，每句两路各几百帧。

## 改动

各级旋转因子在模块加载时按 NFFT 算好一次（与逐次计算的表达式相同，Float64Array 保存，值逐位相同）；交换改为临时变量。

## 验证

- 新旧 `features` 对 5 段合成信号的输出（`db`、`bands`）逐位相同，回声判断结果不变。
- 10 秒音频的 `features`：36 ms → 10 ms（约 3.8 倍，本机空闲时）。
- typecheck / test（含 echo 用例）/ build / docs:check 通过。

## 后续（未做）

会议很长时每 20 秒一次的整体重新归类（`regroup`，计算量随句子数平方增长）也在主进程执行；先观察本次提速后的效果。
