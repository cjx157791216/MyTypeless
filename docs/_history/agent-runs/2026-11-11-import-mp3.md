# 2026-11-11 导入录音支持 MP3（D-046 修订）

## 范围

- 关联 D-046（原 ⑥「暂只支持 WAV，mp3 等以后再做」的「以后」）、GAP-029、MEET-034/035。
- 会议「导入录音」在 WAV 之外支持 MP3（MPEG-1/2/2.5 Layer 1/2/3，含 VBR、带 ID3v2 标签的文件）；m4a 等其他格式仍不做。

## 改动

- `src/main/meeting/import-audio.ts`：新增按文件头认格式 `sniffAudio` / `readAudioInfo` / `convertAudio`；MP3 时长靠 `Mp3FrameScan` 逐帧扫帧头累计（VBR 也准确，跳 ID3v2、垃圾字节重同步、分块与整读一致）；解码用 `mpg123-decoder`（mpg123 的 WASM 版，MIT / LGPL-2.1）流式解码，下混 + `Resampler` 重采样到 16kHz 单声道，按 256KB 块读写。
- `src/main/meeting/index.ts`：`readWavInfo` / `convertWav` 换成 `readAudioInfo` / `convertAudio`，其余流程不变。
- `src/main/index.ts`：文件对话框过滤器放宽到 `wav`、`mp3`。
- `electron.vite.config.ts`：主进程 `externalizeDepsPlugin` 排除 `mpg123-decoder`、`@wasm-audio-decoders/common`（纯 ESM 包，Electron 33 的 asar 不支持 ESM，打进产物而非留在 node_modules）。
- `test/fixtures/import-audio-44k.mp3`（3 秒 440Hz 44.1kHz 立体声 64kbps）、`import-audio-8k.mp3`（2 秒 500Hz 8kHz 单声道 24kbps）：ffmpeg 生成的解码 fixture（已校准幅度 ≈0.5）。
- 文档：需求 §26、验收 MEET-035、D-046（决策原文追加修订）、决策索引、STATUS、IPC 契约、词汇表、GAP-029、meeting 目录 AGENTS.md、第三方声明（mpg123-decoder MIT 全文 + mpg123 LGPL-2.1 声明）。

## 验证

- `npm run typecheck`、`npm run test`（182 个：170 通过、12 todo）、`npm run build` 全部通过；`test/meeting-import.test.ts` 11 个全过。
- 主进程产物验证：`out/main/chunks/*.js` 单独 require（纯 CJS、不经 node_modules，等价打包版 asar 场景）能解码 fixture（132300 样本 @44100）。
- 已知偏差：帧头数出的 MP3 时长含 LAME 编码器延迟与尾部填充（约 0.2s，8kHz 单声道最明显）；只影响「按修改时间倒推开始时间」的精度与时长显示，不影响转码（解码经 gapless 裁剪，长度准确）。
