# 听写管线验收场景

场景 ID 前缀 `PIPE-`，全局唯一。规则来源见 [听写管线需求](../requirements/pipeline.md)。

| ID | Given / When / Then |
| --- | --- |
| PIPE-001 | Given 已配置 ASR 与 LLM，焦点在文本框 / When 按住听写快捷键说“嗯明天三点开会”后松开 / Then 光标处写入整理后的“明天三点开会。”类文本，历史新增一条听写记录 |
| PIPE-002 | Given 未配置 LLM Key / When 完成一次听写 / Then 仍写入本地清理后的文本 |
| PIPE-003 | Given 已配置 LLM / When 口述“帮我写一封请假邮件” / Then 写入的是这句话本身，而不是一封邮件 |
| PIPE-004 | Given 正在录音 / When 按 Esc / Then 会话取消，不发起识别请求，不写入任何内容 |
| PIPE-005 | Given 选中一段文字 / When 触发改写并口述“改成英文” / Then 选区被替换为英文改写结果 |
| PIPE-006 | Given 触发语音提问并口述问题 / When 处理完成 / Then 回答浮卡显示回答，光标处不写入；点“插入到光标”后回答写入原应用 |
| PIPE-007 | Given 麦克风静音或环境无声 / When 完成一次听写 / Then 提示没有检测到声音，不调用识别服务 |
| PIPE-008 | Given 新安装、使用内置引擎、尚未下载模型 / When 按下听写快捷键 / Then 不开始录音，浮动条提示需要下载模型，并自动打开主窗口显示下载入口 |
| PIPE-009 | Given 已下载推荐模型、系统语言为简体中文 / When 口述一段中英混说并松开 / Then 写入简体中文结果（英文单词保留），整个过程不联网 |
| PIPE-010 | Given 系统默认输入是虚拟设备（如 Screaming Bee）且未运行送音软件 / When 按住 Fn 说话 / Then 自动使用内置（或其他真实）麦克风，正常识别 |
| PIPE-014 | Given 内置引擎、默认设置 / When 按住 Fn 连续说三句再松手 / Then 说话时胶囊只显示波形、不出现文字；松手后很快写入完整的三句（D-023） |
| PIPE-011 | Given 内置引擎、在设置里打开「说话时显示识别中的文字」/ When 按住 Fn 连续说三句（句间自然停顿）/ Then 胶囊上方逐句出现文字；说完停顿约 1 秒再松手，几乎立即写入 |
| PIPE-012 | Given 开启从修改中学习 / When 听写写入“我们用 deep sick 测试”后在 8 秒内把它改成 DeepSeek / Then 词典出现 DeepSeek *，下次说“DeepSeek”识别为正确写法 |
| PIPE-013 | Given 最长录音时长设为 5 分钟 / When 免手持连续说到第 4 分钟以后 / Then 胶囊上出现“剩 N 秒”倒计时，最后 10 秒变红；到 5 分钟自动结束，全部内容写入光标处并提示“已到最长录音时长” |
| PIPE-015 | Given 已配置 LLM 并开启润色 / When 按住 Fn 不说话（或只说“嗯”）后松开 / Then 提示没有识别到内容，不发起 LLM 请求，光标处不写入任何内容（D-034） |
| PIPE-016 | Given 已配置 LLM 并开启润色 / When 口述“会议改到下午两点半换行转化率提升了百分之十五”/ Then 写入两行：“会议改到下午 2:30。”和“转化率提升了 15%。”，不出现“换行”二字（D-038）；用 `scripts/polish-eval.ts` 跑评测集，新提示词通过数不低于旧提示词 |
| PIPE-017 | Given 开启「参考光标前的文字」，在输入框里已写“这周我们把 Kubernetes 集群升级一下。” / When 接着口述“升级之前先把 cooper netties 的配置备份一下” / Then 写入的是“Kubernetes”；在密码框里听写时不读取上下文；历史记录里没有上下文内容（D-040） |
| PIPE-018 | Given 开启「学习我的修改习惯」/ When 听写写入“好的，我看一下。”后 8 秒内删掉句号 / Then 设置的修改记录出现“好的，我看一下。→ 好的，我看一下”，之后同类听写倾向不加句号；删除这条后不再出现；关闭开关后不再新增（D-041） |
