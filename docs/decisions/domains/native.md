| D-007 | **自动写入方式。** `injectMethod=auto` 时，结果不超过 160 字且不含换行则逐字键入（不占用剪贴板）；否则直接粘贴（逐字键入慢，且换行在聊天类应用里会直接发送消息）。用户仍可在设置中强制“仅键入”或“仅粘贴”。确认：项目负责人，2026-10-14（关闭 B-004） |
| D-010 | **按住 Fn 说话的交互。** 主键默认 Fn：按住说话、松开写入；轻按（0.3 秒内松开）进入免手持，再按一下结束；开始时若有选中文字自动转为改写，不需要单独的改写键；Fn+空格 语音提问、Fn+Shift 翻译（按一下开始，再按一下或按主键结束）；浮动条为屏幕底部居中的小胶囊（按住时只显示波形，免手持时显示取消/完成，写入后立即消失）。不拦截 Fn 键本身的系统事件，由主窗口引导把「按下 🌐 键时」设为「无操作」。旧默认快捷键（⌥+空格 等）自动迁移。确认：项目负责人，2026-10-14 |
| D-035 | **开始 Windows 移植，默认主键右 Ctrl（修订 D-006）。** 接受社区贡献的 Windows 移植（GAP-008），macOS 仍为主平台。Windows 键盘的 Fn 系统读不到，主键默认右 Ctrl：按住说话、轻按免手持，翻译右 Ctrl+Shift、语音提问右 Ctrl+空格，交互与 D-010 相同；没有右 Ctrl 的键盘可在设置里改为右 Shift、右 Alt。macOS 上区分左右的修饰键只能单独按下触发，不能当组合修饰（`rctrl+space` 这类写法判为无效）。确认：项目负责人，2026-10-17 |
| D-043 | **🌐 键兼容与表情面板提醒（补充 D-010）。** ① 有的键盘 / 系统版本把 🌐 键报为 179 号键（keyDown/keyUp），也有 63 号（Fn 修饰键）与 179 号都报的：两种都认作 Fn，同一次按键只算一次；179 号键不吞。原来按住 Fn 时收到 179 会被当成“按了别的键”而放弃本次录音、只发 179 的 Mac 完全触发不了，用户看到的是按 Fn 只弹表情面板。② 松开 Fn 弹表情面板由系统在事件监听之下处理，拦不住：系统「按下 🌐 键时」不是「无操作」时，用 Fn 开始录音就在胶囊上提醒改为「无操作」，这次听写写完后自动打开键盘设置（每次启动最多一次；录音中不打开，避免抢走焦点）；不改用户的系统设置（未公开接口、崩溃时可能来不及恢复）。确认：项目负责人（选择“按 Fn 时就地提醒”），2026-10-20 |
